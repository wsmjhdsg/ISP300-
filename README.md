## 项目简介

**ISP300 自动化烧录工具** 是一款基于 Python + Tkinter 开发的桌面应用，主要用于简化和自动化 ISP300 烧录器的操作流程。

### 核心思路

1. **配置烧录器软件路径** — 指定要自动化的目标程序（如 ISP300 的快捷方式）
2. **记录屏幕点击位置** — 通过监听鼠标点击，记录界面上按钮/菜单项的坐标及按键方式（左键/右键/双击）
3. **编辑自动化步序** — 为不同"机种 + 累进"组合定义一套步骤（点击/输入/按键/等待）
4. **一键执行** — 启动软件 → 等待加载 → 依次执行自动化步骤（鼠标平滑移动到目标 → 点击）

### 适用场景

- 需要频繁操作相同烧录流程的工厂/车间环境
- 不同机种/版本需要不同操作步骤的场景
- 减少人工重复操作、提高烧录一致性

## 功能概述

本工具提供以下 4 大核心功能模块：

| 功能模块 | 入口位置 | 说明 |
|---------|---------|------|
| **① 烧录器设置** | 设置 → 烧录器设置 | 配置 ISP300 烧录器软件的路径，支持测试启动 |
| **③ 点击位置编辑** | 设置 → 点击位置编辑 | 通过后台监听鼠标点击来记录坐标（左键/右键/双击），也可手动修改 |
| **② 机种编辑** | 设置 → 机种编辑 | 管理"机种"与机种下的"累进"，并为每个"机种+累进"组合编写独立的步序文件 |
| **开始烧录** | 主窗口绿色按钮 | 启动烧录器软件 → 倒计时 8 秒 → 依次执行自动化步骤 → 显示日志与进度 → 弹窗提示完成 |

### 支持的自动化步骤类型

| 类型 | 标识符 | 功能 |
|-----|--------|------|
| **点击** | `click` | 调用已记录的坐标名称执行点击，或直接填入 X/Y 坐标。**必须明确指定按键方式（left/right/double）** |
| **输入文本** | `type` | 模拟键盘输入字符串，**区分大小写**，如 `Hello` 与 `hello` 不同 |
| **按键** | `key` | 按下单个按键（如 `enter`、`tab`、`f1`、`space` 等） |
| **等待** | `wait` | 暂停若干秒（用于等待软件响应/加载） |

### 重要特性（⭐ 本次改动相关）

- **鼠标平滑移动**：执行点击时，鼠标平滑移动到目标坐标 → 短暂停顿 → 点击，过程可视化
- **按键方式必须明确**：所有点击操作的按键方式（左键/右键/双击）必须显式指定，不再有"默认"模糊选项
- **文本区分大小写**：输入文本严格区分大小写，`ABC` ≠ `abc`
- **独立步序文件**：每个"机种 + 累进"组合对应独立的 JSON 步序文件（`config/steps/机种名_累进值.json`），便于备份、迁移和管理
- **更大更清晰的 UI**：所有窗口尺寸加大，最小尺寸限制，避免内容被挤压看不见
- **操作按钮清晰命名**：`➕新增`、`✎重命名`、`🗑删除`、`⬆上移`、`⬇下移` 等，一目了然
- **执行完成弹窗**：烧录完成后弹窗提示完成及统计信息（总步数 + 耗时）
- **实时状态显示**：执行过程中状态栏实时显示 "执行中: 5/12" 等进度

## 依赖环境

### 运行环境

- **Python**: 3.8 及以上（推荐 3.10+）
- **操作系统**: Windows 10 / Windows 11（推荐，因为 `os.startfile` 用于启动外部程序）

### 第三方库

| 库名 | 用途 | 安装命令 |
|-----|------|---------|
| **pyautogui** | 模拟鼠标平滑移动、点击、键盘输入、按键操作 | `pip install pyautogui` |
| **pynput** | 监听鼠标点击事件（用于记录坐标及按键方式） | `pip install pynput` |

> **说明**: Tkinter 是 Python 标准库自带的 GUI 框架，无需额外安装；`json`、`threading`、`os`、`subprocess`、`time` 均为标准库。

### 一键安装依赖

```bash
pip install pyautogui pynput
```

## 使用说明

### 3.1 烧录器设置

**入口**: 主窗口左上角 `⚙ 设置 ▾` → `① 烧录器设置`

该对话框用于配置 ISP300 烧录器软件的路径（可选配置，如不配置则不自动启动软件，直接执行步序）：

| 字段 | 说明 |
|-----|------|
| 软件路径 | 填入 ISP300 程序 exe 或快捷方式（.lnk）的完整路径 |
| `浏览...` 按钮 | 通过文件选择器定位程序 |
| `测试启动` 按钮 | 立即尝试启动填写的路径，验证是否正确 |
| `保存` | 将路径写入 `config/burner.json` |

操作流程：
1. 点击 `浏览...` 选择 ISP300 的可执行文件或桌面快捷方式
2. 点击 `测试启动` 验证路径是否可用（状态栏显示绿色"已启动"或红色"启动失败"）
3. 点击 `保存` 确认设置

---

### 3.2 点击位置编辑

**入口**: 主窗口左上角 `⚙ 设置 ▾` → `③ 点击位置编辑`

该对话框用于管理屏幕上的点击坐标（例如 ISP300 软件中的"开始"按钮、"确定"按钮、某个菜单项等）。

**重要**: 记录坐标时，**左键/右键/双击都会被自动识别并记录**，后续在步序中调用该坐标时沿用此按键方式。

#### 界面组成

```
┌───────────────────────────────────────────────────┐
│ [➕ 新增坐标(点击记录)] [✎ 修改选中] [🗑 删除选中]  │
│  状态栏: [已记录] 开始按钮 = (450,220) 左键点击    │
├───────────────────────────────────────────────────┤
│    名称       │  X  坐标 │ Y 坐标 │ 按键方式       │
├───────────────┼──────────┼────────┼────────────────┤
│  开始烧录按钮 │   245    │  380   │ 左键单击       │
│  确定按钮     │   560    │  420   │ 左键单击       │
│  文件菜单     │   50     │  30    │ 右键单击       │
│  ...                                                      │
└───────────────────────────────────────────────────┘
                     ↑ 双击行可手动编辑坐标和按键方式
```

#### 新增坐标流程

1. 点击 `➕ 新增坐标(点击记录)`
2. 弹窗输入该坐标的名称（如"开始烧录按钮"、"确认对话框"）
3. 本工具窗体自动半透明隐藏，顶部出现提示：`[记录中] 请在目标位置点击一次(左键/右键/双击)... 按 ESC 取消`
4. **将鼠标移到 ISP300 软件的目标按钮/位置上点击一次**（左键/右键/双击都会被识别）
5. 工具窗口恢复显示，坐标及按键方式已自动记录并出现在列表中

> **快捷键**: 记录过程中按 `ESC` 可取消本次记录

#### 其他操作

| 操作 | 方式 | 说明 |
|-----|------|------|
| 删除坐标 | 选中行 → `🗑 删除选中` | 删除不需要的坐标 |
| 手动编辑坐标 | 双击列表中的行 | 手动修改 X/Y 值和按键方式（左键单击/右键单击/左键双击） |

#### 步骤操作按钮（更清晰的命名）

| 按钮 | 功能 |
|-----|------|
| `➕ 在末尾新增` | 在步骤列表末尾添加新步骤 |
| `↩ 在选中上方插入` | 在当前选中步骤之前插入新步骤 |
| `↪ 在选中下方插入` | 在当前选中步骤之后插入新步骤 |
| `✎ 修改选中` | 打开当前选中步骤的编辑对话框（或双击步骤行） |
| `🗑 删除选中` | 删除当前选中的步骤，有确认提示 |
| `⬆ 上移` | 将选中步骤上移一位，到顶部时提示无法再上移 |
| `⬇ 下移` | 将选中步骤下移一位，到底部时提示无法再下移 |

#### 新增步骤时的 4 种类型配置（⭐ 明确按键/区分大小写）

**① 点击 (click)** — 调用已记录的坐标执行点击

| 字段 | 说明 |
|-----|------|
| 选择已记录的坐标 | 下拉选择已在"点击位置编辑"中记录的名称（**推荐方式**） |
| 或手动填写坐标 | X / Y （当不使用已记录坐标时，二选一） |
| **按键方式（必须选择）** | `left 左键单击` / `right 右键单击` / `double 左键双击` — **必须明确选择，不再有"默认"选项** |
| 步骤后等待 | 点击完成后暂停的秒数（默认 0.5s） |

**② 输入文本 (type)** — 在当前光标位置输入字符串，**区分大小写**

| 字段 | 说明 |
|-----|------|
| 输入文本内容(区分大小写) | 要输入的字符串内容（多行文本框）。**Hello ≠ hello，大小写不同**。中文需通过剪贴板方案（见常见问题Q3） |
| 步骤后等待 | 输入完成后暂停的秒数（默认 0.3s） |

**③ 按键 (key)** — 按下单个按键

| 字段 | 说明 |
|-----|------|
| 按键名称 | 如 `enter`、`tab`、`esc`、`f1`、`f2`、`space`、`delete`、`backspace`、`ctrl`、`alt`、`shift` 等。下方提供常用按钮快捷选择 |
| 常用按键快捷按钮 | `ENTER` `TAB` `ESC` `SPACE` `F1` `F2` `DELETE` 快捷填入 |
| 步骤后等待 | 按键后暂停的秒数（默认 0.3s） |

> 💡 **常见按键名称参考**: enter, tab, esc, f1~f12, space, backspace, delete, insert, home, end, pageup, pagedown, up, down, left, right, capslock, numlock

**④ 等待 (wait)** — 让程序暂停若干秒（非常重要！）

| 字段 | 说明 |
|-----|------|
| 暂停多少秒后继续下一步 | 暂停时长（秒），可填小数如 1.5。下方有 `0.5秒` `1秒` `2秒` `3秒` `5秒` 快捷按钮 |

> 💡 **为什么需要等待？**
> - ISP300 软件可能需要几秒来响应操作（如加载文件、弹出对话框）
> - 如果步骤太快，下一次点击可能落在错误的位置
> - 推荐在每个"点击"操作后至少等待 0.5~1 秒，重要操作（如弹出确认框）后等待 2~3 秒

#### 保存

点击 `💾保存步序` 后，步骤会写入独立文件 `config/steps/机种名_累进值.json`。

## 配置文件格式

所有配置以 JSON 格式保存在 `config/` 目录下，程序首次运行时自动创建目录及子目录 `steps/`。

### 5.1 burner.json — 烧录器软件路径

结构最简单，仅保存一个键值对：

```json
{
  "path": "C:\\ISP300\\ISP300.exe"
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| `path` | string | 烧录器软件可执行文件或快捷方式的完整路径，留空 `""` 表示跳过自动启动 |

---

### 5.2 click_points.json — 点击坐标库

一个以坐标名称为 key 的字典对象，**每条坐标记录了按键方式（left/right/double）**：

```json
{
  "开始烧录按钮":   { "x": 245, "y": 380, "button": "left"  },
  "确定按钮":       { "x": 560, "y": 420, "button": "left"  },
  "文件菜单":       { "x": 50,  "y": 30,  "button": "right" },
  "输入框":         { "x": 300, "y": 150, "button": "left"  }
}
```

| 字段 | 类型 | 说明 |
|-----|------|------|
| `x` | number | 屏幕 X 坐标（像素，原点在屏幕左上角） |
| `y` | number | 屏幕 Y 坐标（像素） |
| `button` | string | **必须**，点击方式：`left`（左键单击）/ `right`（右键单击）/ `double`（左键双击） |

> **提示**: 如果你更换了显示器分辨率或 ISP300 软件不在固定位置，需要重新记录所有坐标。

---

### 5.3 machines.json — 机种 / 累进结构

只保存机种和累进的层级关系，**不保存步骤**（步骤移到独立文件）：

```json
{
  "VRV6":  ["V1.0", "V1.2", "V2.0"],
  "ABC":   ["V2.1"],
  "Model": ["R1", "R2"]
}
```

| 结构 | 类型 | 说明 |
|-----|------|------|
| 顶层 key | string | 机种名称 |
| 顶层 value | array | 该机种下的累进名称列表 |

---

### 5.4 steps/机种_累进.json — 独立步序文件（⭐ 新方案）

**每一个 `机种 + 累进` 组合对应一个独立的 JSON 文件**，放在 `config/steps/` 目录下，文件名格式为 `机种名_累进值.json`（特殊字符会被安全处理）。

例如 `config/steps/VRV6_V1.0.json` 的内容是一个步骤数组：

```json
[
  { "type": "click", "point_name": "开始烧录按钮", "button": "left",  "wait": 0.5 },
  { "type": "wait",  "seconds": 2.0 },
  { "type": "type",  "text": "SN-12345",          "wait": 0.3 },
  { "type": "key",   "key": "enter",              "wait": 0.3 },
  { "type": "click", "point_name": "确定按钮",    "button": "left",  "wait": 1.0 }
]
```

**优势**:
- 文件独立管理，便于单独备份、迁移某一个配置
- 主 `machines.json` 更简洁，避免文件过于臃肿
- 便于手动编辑/排查问题

---

### 5.5 步骤（Step）的完整 JSON 结构

**① click 步骤**（调用已记录坐标）：
```json
{
  "type": "click",
  "point_name": "开始烧录按钮",
  "button": "left",
  "wait": 0.5
}
```

**② click 步骤**（直接填坐标）：
```json
{
  "type": "click",
  "x": 245,
  "y": 380,
  "button": "left",
  "wait": 0.5
}
```

**③ type 步骤**（输入文本，区分大小写）：
```json
{
  "type": "type",
  "text": "SN-12345",
  "wait": 0.3
}
```

**④ key 步骤**（按键）：
```json
{
  "type": "key",
  "key": "enter",
  "wait": 0.3
}
```

**⑤ wait 步骤**（等待）：
```json
{
  "type": "wait",
  "seconds": 2.0
}
```

> **说明**: 
> - 所有步骤中的 `wait` 字段表示该步骤执行完成后暂停的秒数
> - `button` 字段**必须显式给出** `left` / `right` / `double` 三选一，不再支持"默认"
> - `text` 字段区分大小写，`Hello` 和 `hello` 会产生不同输入

## 核心模块说明

### 6.1 core/config_manager.py — 配置管理

**设计目标**: 集中管理所有 JSON 配置文件的读写，为 UI 层提供统一的 CRUD 接口。采用单例模式（Singleton）确保全局只有一份配置实例。

**步序文件管理**：为避免 `machines.json` 臃肿，步骤数据独立保存到 `config/steps/机种_累进.json` 文件中，由 ConfigManager 透明管理路径拼接、重命名、删除。

```python
from core.config_manager import ConfigManager

config = ConfigManager()        # 单例，首次调用时初始化
```

**关键 API 概览**：

| API 分类 | 方法签名 | 说明 |
|---------|---------|------|
| 烧录器路径 | `get_burner_path()` | 返回已保存的软件路径字符串 |
| | `set_burner_path(path)` | 保存并写入 JSON |
| 机种管理 | `get_machine_names()` | 返回所有机种名称的 list |
| | `add_machine(name)` | 新增机种，成功返回 True |
| | `rename_machine(old, new)` | 重命名机种，**同时移动对应的所有步序文件** |
| | `delete_machine(name)` | 删除机种及其所有累进，**同时删除对应的所有步序文件** |
| 累进管理 | `get_machine_rates(machine)` | 返回某机种下所有累进的 list |
| | `add_rate(machine, rate)` | 为机种新增累进 |
| | `rename_rate(machine, old, new)` | 重命名累进，**同时重命名对应的步序文件** |
| | `delete_rate(machine, rate)` | 删除累进，**同时删除对应的步序文件** |
| 步序管理 | `get_steps(machine, rate)` | 从 `steps/机种_累进.json` 读取步骤数组 |
| | `set_steps(machine, rate, steps)` | 将步骤数组写入对应的独立文件 |
| | `has_steps(machine, rate)` | 判断该组合是否配置了步骤 |
| | `get_steps_file(machine, rate)` | 返回步序文件的完整路径 |
| 点击坐标 | `click_points` | 直接访问内部字典 |
| | `get_click_point(name)` | 获取单个坐标的 dict |
| | `add_click_point(name, x, y, button)` | 新增/覆盖坐标，button 为 left/right/double |
| | `update_click_point(name, x, y, button)` | 更新已有坐标 |
| | `delete_click_point(name)` | 删除坐标 |

**内部实现要点**：
- `_safe_name(name)` — 将机种/累进名称中的非法文件名字符替换为 `_`，确保文件名有效
- `_step_file(machine, rate)` — 拼接步序文件路径：`config/steps/<safe_machine>_<safe_rate>.json`
- `_load_json(filepath, default)` — 带异常处理的 JSON 读取，文件不存在或格式错误时返回默认值
- `_save_json(filepath, data)` — 以 UTF-8 编码写入 JSON，缩进 2 空格方便人工查看
- `_migrate_old_format()` — 兼容旧版格式（步骤内嵌在 machines.json 中），首次使用新版时自动迁移数据

### 6.2 core/recorder.py — 点击位置记录器

**设计目标**: 通过 `pynput` 库监听全局鼠标事件，捕获一次左/右键/双击点击后自动停止，并通过回调返回坐标和按键方式。

```python
from core.recorder import ClickRecorder

recorder = ClickRecorder()

def on_captured(point):
    print(f"捕获到点击: {point}")
    # {'x': 245, 'y': 380, 'button': 'left'}  # 或 'right'/'double'

recorder.start(callback=on_captured)   # 启动监听，点击一次后自动停止
# recorder.stop()                      # 如需主动取消调用此方法
```

**关键特性**：
- **一次性监听**: 捕获一次点击后自动停止监听，避免误操作记录
- **回调式 API**: 通过 callback 函数异步通知结果，不阻塞主线程（GUI 仍可响应）
- **按键识别**: 区分左键、右键和双击，分别标记为 `left` / `right` / `double`

> **注意**: 该模块使用独立线程运行鼠标监听，UI 层在 callback 中更新界面时需注意线程安全（Tkinter 需要在主线程更新界面）。

### 6.3 core/simulator.py — 模拟操作模块（⭐ 本次优化重点）

**设计目标**: 封装 `pyautogui` 的所有自动化操作（**平滑移动鼠标 → 点击** / 输入 / 按键 / 等待），并提供"执行单个步骤"、"批量执行步骤序列"的高层接口。

**核心改进**：
- **点击操作可视化**：不再直接点击，而是 `pyautogui.moveTo(x, y, duration=0.2)` 平滑移动 → 停顿 0.2s → 点击，让操作者看清过程
- **按键方式必须明确**：`button` 参数必须是 `left` / `right` / `double`，不再有默认模糊值
- **文本输入区分大小写**：`pyautogui.typewrite` 天然区分大小写，无需特殊处理
- **执行完成统计**：`execute_steps` 完成后输出完成统计（总步数 + 成功数 + 耗时）

**核心静态方法**：

| 方法 | 说明 |
|-----|------|
| `launch_program(path)` | 启动外部程序（Windows 下用 `os.startfile`，跨平台用 `subprocess`） |
| `click(x, y, button, wait)` | **鼠标平滑移动到坐标 → 停顿 → 点击**，支持 left/right/double |
| `type_text(text, wait)` | 模拟键盘输入字符串，**区分大小写** |
| `press_key(key, wait)` | 按下单个按键 |
| `wait(seconds)` | 暂停指定秒数 |
| `execute_step(step_dict, click_points_map)` | 执行单个步骤（dict），返回日志字符串如 "移动到[开始按钮] → 左键点击" |
| `execute_steps(steps, click_points, progress_cb, log_cb)` | 批量执行步骤数组，支持进度和日志回调，**执行完成时输出统计信息** |

**关键逻辑 — execute_step 的类型分派**（参考 `simulator.py:96-140`）：

```
step["type"]
    ├── "click" → 优先使用 point_name 查坐标表，找不到则用 x/y
    │              button 必须是 left/right/double 之一
    │              日志: "移动到[开始按钮](245,380) → 左键点击"
    ├── "type"  → 直接 type_text(text)
    │              日志: "输入文本(区分大小写): 'SN-12345'"
    ├── "key"   → press_key(key)
    │              日志: "按键: [enter]"
    └── "wait"  → wait(seconds)
                   日志: "等待 2.0 秒"
```

**进度与日志回调的使用示例**（参考主窗口 `_start_burn`）：

```python
summary = Simulator.execute_steps(
    steps,
    config.click_points,
    progress_callback=lambda v: print(f"进度: {v}%"),
    log_callback=lambda msg: print(msg)
)
# summary = {"total": 8, "success": 8, "elapsed": 12.3}
```

> **容错设计**: 每个模拟操作都被 `try-except` 包裹，单个步骤失败不会终止整个流程，日志中会反映异常。

### 6.4 ui/main_window.py — 主窗口（⭐ 更大窗口 + 完整日志）

**设计目标**: 作为程序的主交互界面，提供机种/累进的下拉选择、一键烧录按钮、执行进度条和**更详细的运行日志**。

**界面布局**（720×680，最小 680×600）：
- **顶部**: `⚙ 设置 ▾` 下拉菜单（有序号 ①②③） + 标题
- **中部**: 机种下拉框 + 累进下拉框 + 大号绿色 `▶ 开始烧录` 按钮
- **状态栏**: 实时显示当前状态（等待开始 / 执行中 5/12 / ✓完成）
- **进度条**: 百分比进度条
- **底部**: 大尺寸多行**滚动日志文本框**（字体 Consolas，720x300+ 可视区域）

**烧录线程设计**：
- 烧录过程在独立 `threading.Thread` 中执行（`daemon=True`），避免 GUI 冻结
- 进度/状态/日志更新通过 `self.after(0, lambda: ...)` 回调到 Tkinter 主线程执行
- 按钮在执行期间禁用并改为 `● 执行中...`（橙色背景），完成或异常后自动恢复
- 执行完成后弹出 `messagebox` 提示完成信息

**执行时序**：
```
用户点击"▶ 开始烧录"
    │
    ├─> 校验机种/累进/步骤是否配置
    ├─> 日志输出分隔线 + 配置信息
    ├─> 启动烧录器软件（如已配置路径）
    ├─> 8 秒倒计时（每秒输出 "... N ..." 日志）
    ├─> 依次 execute_step 执行每个步骤
    │    └─> 实时回调更新进度 + 追加日志 + 状态栏 "执行中: N/总数"
    ├─> 输出 "[✓完成]" 日志 + 分隔线
    ├─> 弹出 messagebox.showinfo 提示完成（总步数 + 耗时）
    └─> 状态栏 "✓ 完成! 总步数: N  耗时: X.X秒" (绿色)
```

## 常见问题

### Q1: 点击坐标不准确，步骤落在错误位置怎么办？

**原因**: ISP300 软件的窗口位置/大小在不同运行时不一致，导致屏幕坐标偏移。

**解决**:
1. 每次记录坐标前，先将 ISP300 窗口固定到一个位置（如最大化）
2. 确保显示器分辨率不变（坐标是绝对屏幕坐标，不是窗口内相对坐标）
3. 如果更换显示器或电脑，需要重新记录所有坐标

### Q2: 步骤执行太快导致软件来不及响应？

**解决**: 在每个 `click` 或 `key` 步骤后适当增加 `wait` 值（0.5~2 秒），或在关键步骤之间插入独立的 `wait` 步骤。经验规则：涉及弹窗/文件加载的操作后至少等待 2 秒。

### Q3: 输入文本时中文乱码？

**原因**: `pyautogui.typewrite` 不支持非 ASCII 字符（如中文）。

**解决**:
- 如果 ISP300 只需要输入字母和数字（如序列号 SN-12345），不受影响
- 如需输入中文，需要改用剪贴板方案（如 `pyperclip` 复制 + `Ctrl+V` 粘贴），这属于扩展功能

### Q4: 文本输入区分大小写吗？

**是的**。`Hello` 和 `hello` 会产生不同的输入。工具在输入文本编辑框上也明确标注了"区分大小写"提示。

### Q5: 点击步骤的按键方式必须指定吗？

**是的**。左键/右键/双击必须明确选择，不再有"默认"模糊选项。在"点击位置编辑"中记录坐标时，鼠标的点击方式会自动记录；在步序编辑中调用坐标时，也可以在步骤级别覆盖按键方式。

### Q6: 程序启动时提示找不到 pyautogui 或 pynput？

**原因**: 未安装第三方依赖。

**解决**: 命令行执行 `pip install pyautogui pynput`，确保使用的 Python 解释器与运行 `main.py` 的是同一个。

### Q7: 如何在烧录执行过程中终止？

目前版本没有专门的停止按钮。如果需要紧急终止：
- 手动移动鼠标到屏幕的**左上角** — `pyautogui` 的 Fail-Safe 机制会触发 `FailSafeException`，从而中断自动化
- 关闭工具窗口也可以终止程序（因为自动化线程是 daemon 线程）

### Q8: 配置文件能否手动编辑？

可以。所有 JSON 文件都是纯文本，你可以用任意文本编辑器查看/修改。但推荐通过工具界面编辑以避免语法错误。如果手动编辑后程序无法启动，请检查 JSON 语法（逗号、引号是否匹配）。

**特别注意**: 步序文件现在独立存放在 `config/steps/` 目录下。如果手动编辑 `machines.json` 添加了机种/累进，必须同时创建对应的 `config/steps/机种_累进.json` 文件并写入一个空数组 `[]`。

### Q9: 我想把配置复制到另一台电脑上怎么办？

直接复制整个 `config/` 目录即可。但是请注意：
- 烧录器路径在另一台电脑上可能不同，需要重新配置
- 点击坐标在不同分辨率/窗口位置下可能不准确，需要重新记录
- 步序文件无需修改，但如果机种/累进名称中包含特殊字符，文件名可能不同（已被 `_safe_name` 处理）

### Q10: 烧录时鼠标移动过程太快看不清？

可以调整。打开 `core/simulator.py` 修改类顶部两个参数：

```python
class Simulator:
    MOVE_DURATION = 0.2   # 鼠标移动平滑时间（秒），调大更慢
    MOVE_PAUSE = 0.2      # 到达目标后点击前的停顿（秒）
```
