## 项目简介

**AutoISP300** 是一款基于 **Python + Tkinter** 的 Windows 桌面自动化工具，面向工厂 / 车间中需要**反复操作同一套烧录流程**的场景。

核心思路一句话：**把"人在 ISP300 软件上点鼠标、敲键盘"的流程，录制成可复用的配置，然后让程序替你执行。**

数据模型为「**机种 → 累进**」两级结构：

- **机种**：产品型号 / 项目名称（如 `VRV6`）；
- **累进**：同一机种下的不同烧录版本 / 物料（如 `2P787591-1`）。

每一个「机种 + 累进」组合对应一份**独立的步序文件**，互不干扰，方便单独备份与迁移。

程序内目标操作定位支持两种方式，互为补充：

| 定位方式 | 原理 | 优点 | 缺点 |
|---------|------|------|------|
| **屏幕坐标点** | 录制鼠标在屏幕上的绝对坐标（X, Y）+ 按键方式 | 通用，任何窗口都能点 | 窗口移动 / 分辨率变化后坐标失效 |
| **UIA 控件点** | 通过 pywinauto 按 `控件类型 / 标题 / automation_id` 匹配 ISP300 窗口内的控件 | 抗窗口移动与缩放，更稳定 | 仅对暴露 UIA 接口的控件有效 |

## 核心功能

| 功能 | 入口 | 说明 |
|------|------|------|
| **机种 / 累进管理** | `设置 → 机种编辑` | 增删改机种与累进；选中组合后可直接进入步序编辑；删除时**级联清理**对应的步序文件 |
| **步序编辑** | 机种编辑对话框 → `编辑步序` | 为当前「机种 + 累进」编排步骤：支持 7 类步骤的末尾新增 / 上下方插入 / 修改 / 删除 / 上移 / 下移 |
| **点击位置编辑** | `设置 → 点击位置编辑` | ① **录制坐标**：把窗口变半透明后在实际软件界面上点一下，自动识别左键 / 右键 / 双击；② **枚举控件**：读取 ISP300 窗口内可交互控件列表，挑选后按 UIA 标识保存为"控件点" |
| **一键执行** | 主窗口 `开始执行` | 选择机种 + 累进 → 后台线程逐条执行该组合的步序 → 实时进度条、状态栏、滚动日志；执行中按 **ESC** 或点 `停止` 主动中止 → 完成 / 停止弹窗汇总（含成功与失败分项统计） |

### 支持的 7 类步骤

| 步骤 | 类型标识 | 作用 |
|------|---------|------|
| **打开软件** | `launch` | 启动外部程序（.exe / .lnk），可配合后续等待步骤留出加载时间 |
| **点击** | `click` | 调用已记录的"坐标点 / 控件点"，或直接填 X/Y 坐标；按键方式显式选择左键 / 右键 / 双击 |
| **选择文件** | `openfile` | 自动填充弹出的系统"打开文件"对话框（选固件等）：`path` 固定路径 / `latest` 目录内自动选最新 / `pick` 每次执行前手选 |
| **输入文本** | `type` | 在当前光标处逐字符模拟输入（区分大小写；执行前把输入法临时切到英文模式，结束后恢复） |
| **按键** | `key` | 按下单个按键（enter / tab / esc / f1~f12 / space …） |
| **等待** | `wait` | 暂停指定秒数（可小数），用于等待软件响应、弹窗出现 |
| **烧录判定** | `waitresult` | 轮询 ISP300 的"烧录完成"弹窗（标题 `COMPLETE`、正文 `Verify OK`），收到即判定成功并自动点"确定"关闭；超时未收到按失败处理 |

### 关键特性

- **两种定位方式并存**：坐标点适合"通用盲点"，控件点适合"ISP300 的按钮 / 下拉框 / 输入框"，控件点对窗口位置不敏感。
- **录制即带按键方式**：录制坐标时左键 / 右键 / 双击自动识别并记录，步序中调用即沿用（步序中也可显式覆盖）。
- **执行安全**：执行期间启用**全局键盘监听**——按 **ESC** 即刻中止；**鼠标不再触发中止**（可自由操作鼠标，产线振动也不会误停）。
- **失败即中止（防烧错）**：默认任一环节失败（校验不通过 / 步骤执行失败，如控件未找到、未等到烧录完成弹窗）会**立即停止后续步骤**，避免带着错误继续操作（尤其防止未选中正确目标就点 `Send Data` 烧错芯片）；主窗口「失败即中止」开关可关闭（关闭后失败步骤计失败并继续）。
- **输入法保护**：输入文本前仅做 **中/英模式切换**（临时关闭当前中文输入法使其输出英文，等价于语言栏"中"切"英"），**不切换键盘布局、不新增英文输入法**；执行结束自动把中文输入法重新开启。
- **执行容错**：单个步骤失败不会中断整条流程，日志中记录异常；结束时统计总步数、成功数、耗时。
- **线程化 UI**：执行跑在后台守护线程，主界面不冻结；进度 / 日志通过 `after()` 安全回主线程刷新；执行中按钮置灰变橙，结束后恢复。
- **绿色免安装**：配置 `config/` 与日志 `logs/` 始终创建在**程序所在目录**（源码运行=项目根；打包运行=exe 旁），整个文件夹拷贝即迁移，零系统写入。
- **浅色工业风 UI**：铝灰底 + 深钢灰铭牌栏 + 信号橙主操作 + 工控红停止 + 状态指示灯；配色 / 字体 / 尺寸全部收敛到 `core/constants.py` 的 `UISettings`，ttk 主题由 `ui/styles.py` 统一应用，对话框换肤自动跟随。
- **自动选择文件**：`openfile` 步骤等待目标软件弹出的"打开文件"对话框（最长 10s，可被"停止"打断），自动填入文件路径并确认；对话框控件结构因系统新旧而异，程序内置 UIA/win32 多候选定位器逐级尝试，任一级成功即通过；仍失败则明确报错并交人工完成该次选择。
- **ESC 一键中止**：执行中按 **ESC**（全局监听）或点 `停止` 按钮随时中止（`wait` 长等待也能即时响应）。
- **烧录结果判定（waitresult）**：轮询 ISP300 标题为 `COMPLETE` 的"烧录完成"弹窗（默认超时 120s、每 0.5s 查一次、可被"停止"打断）——正文含 `Verify OK` 判定**成功**并自动点「确定」关窗；**超时未收到或内容非 OK 一律判定失败**（宁严勿松，不把"没弹窗"当成功）；建议紧跟 `Send Data` 步骤，用于确认整条流程真正烧录完成。
- **列表行点击（控件点健壮性）**：ListItem 控件点若标题为**纯数字**（录制时为空槽位行，如 `18`），执行时不再按标题文本匹配，而是解释为**列表行号**定位（`Read I.S.P` / `LOAD` 后行内容刷新、空槽被设备占用导致标题变化也不失配）；点击失败时会自动把列表当前全部行 dump 进日志，便于一次定位。
- **配置写入安全**：所有 JSON 保存改为**原子写**（临时文件 + `os.replace`），崩溃 / 断电不会损坏配置；读取到损坏 JSON 时自动改名留存（`.corrupt-*`）供人工找回，而非静默丢数据。
- **数据校验层**：新增 `core/validation.py`，执行前逐条校验步骤（未知类型 / 缺字段 / 引用的位置点不存在等），非法步骤在日志中明确"跳过 + 原因"并计入失败，不再被容错吞成难懂日志。
- **长文本粘贴**：`type` 步骤文本超 40 字符时自动改走"剪贴板 + Ctrl+V"（输入结束后自动清空剪贴板），提速并规避逐键转义问题。
- **日志区截断**：界面日志仅保留最近 1500 行（完整 DEBUG 日志仍在 `logs/auto_isp.log`），长时间执行不卡。
- **旧数据自动迁移**：首次运行若检测到旧版 `machines.json`（步骤内嵌在机种下的格式），自动拆分为独立步序文件。

## 快速开始

### 1. 环境准备

- **Python**：3.10+（推荐 3.10+；打包用 3.12）
- **操作系统**：Windows 10 / 11（依赖 Windows 输入法 / 键盘 API）

安装依赖（推荐用虚拟环境；pyautogui / pynput / pywinauto 均在 `pyproject.toml` 中声明）：

```bash
pip install -e .
# 仅开发(跑测试)时额外:
pip install -e ".[dev]"   # 或直接: pip install pytest
```

> Tkinter 为 Python 标准库自带，无需安装。

### 2. 运行

```bash
python main.py
```

### 3. 首次配置流程（按顺序）

1. **设置 → 机种编辑 → 新增机种**（如 `VRV6`）→ 选中后**新增累进**（如 `2P787591-1`）。
2. 保持选中该组合，点击 **编辑步序**：
   - 第一类步骤选 **打开软件（launch）**，浏览选择 ISP300 上位机的 `.exe` 或 `.lnk`；
   - 随后**先插几条"等待"步骤**留出启动时间，再按实际操作流程逐步添加 `点击 / 输入文本 / 按键 / 等待`；
   - 保存步序（写入 `config/steps/机种_累进.json`）。
3. **设置 → 点击位置编辑**：
   - 需要点击 ISP300 界面上"按钮/菜单/输入框"时，推荐**新增控件（枚举 ISP300）**——要求 ISP300 已打开，从枚举列表里挑目标控件（可按关键字过滤）；
   - 若控件无法枚举，则用 **新增坐标（点击记录）**：输入名称后窗口变半透明，在目标按钮上点一次（左键/右键/双击均可），按 `ESC` 可取消。
4. 返回主窗口，选择机种 + 累进，点击 **开始执行**。

> 💡 坐标点是"绝对屏幕坐标"：录制和使用时请保持 ISP300 窗口位置、显示器分辨率一致（最大化最稳妥），否则坐标会偏移。

## 打包与部署（绿色免安装）

### 一键打包

双击 `build.bat`（或命令行执行），脚本将自动：

1. 清空 `PYTHONPATH`（避免 IDE 环境污染）；
2. 若未安装 PyInstaller，从清华镜像自动安装；
3. 清理旧的 `build/`、`dist/`；
4. 以 `--onefile --windowed` 打包，**collect-all** 收集 `pywinauto / pynput / pyautogui`，并嵌入 `dpi.manifest`（DPI 感知，高分屏清晰）；`--icon` 嵌入应用图标（工业风芯片+闪电），`--add-data` 把图标一并打进包，运行期窗口标题栏/任务栏同样显示该图标。

产物：`dist\AutoISP300.exe`。若需复现构建，也可直接执行：

```bash
pyinstaller AutoISP300.spec
```

### 部署迁移

把整个 `dist\` 目录拷贝到目标电脑即可：

```
dist/
├── AutoISP300.exe   ← 双击运行
├── config/          ← 机种 / 坐标 / 步序等已有配置，随包分发
└── logs/            ← 运行日志（可随包带，也可留空由程序重建）
```

- 首次运行会自动在 exe 旁补齐缺失的 `config/`、`logs/`；
- **兼容范围**：Windows 10 / 11（无系统写入，绿色免安装，卸载=删文件夹）。

## 配置文件说明

所有配置均为 **UTF-8 JSON**，位于 `config/`（目录不存在时程序自动创建）。程序退出 / 保存时即时写盘，可直接用文本编辑器查看。

### `config/machines.json` — 机种 / 累进层级

只保存两级名称关系，不保存步骤：

```json
{
  "VRV6": ["2P787591-1", "V1.2"],
  "ABC":  ["V2.1"]
}
```

- 顶层 key：机种名；value：该机种下的累进名列表。

### `config/click_points.json` — 点击位置库

key 为点位名称，value 分两种：

**① 坐标点**（屏幕绝对坐标）：

```json
{
  "CPU选择": { "x": 805, "y": 337, "button": "left" }
}
```

**② 控件点**（UIA 定位，带 `"type": "control"`，任意一两个定位字段命中即可点击）：

```json
{
  "开始烧录按钮": {
    "type": "control",
    "control_type": "Button",
    "title": "开始",
    "auto_id": "",
    "button": "left"
  }
}
```

| 字段 | 说明 |
|------|------|
| `x` / `y` | 屏幕坐标（仅坐标点有） |
| `control_type` / `title` / `auto_id` | UIA 控件标识（仅控件点有，至少一个非空） |
| `button` | 按键方式：`left` / `right` / `double`，录制坐标时自动识别 |

### `config/steps/机种_累进.json` — 步序文件

每个「机种 + 累进」组合对应一个独立文件，文件名为 `机种名_累进名.json`（非法文件名字符自动替换为 `_`）。内容是一个**步骤对象数组**（完整字段见下节示例）。

> 手动增删 `machines.json` 里的机种/累进时，记得同步创建对应 `steps/*.json`（空配置写 `[]` 即可）。

### `config/burner.json` — 烧录器路径（历史保留）

```json
{ "path": "C:/.../ISP300Host_ver5.lnk" }
```

早期版本在"设置"里单独配置烧录器路径、执行前自动启动并倒计时。**当前版本已将"启动软件"做成步序中的 `launch` 步骤**（更灵活：可插在任意位置、可配多个启动），故该文件无界面驱动。**v3 起程序不再读写该文件**，仅保留磁盘上的历史文件供外部参考。

## 步序（步骤）说明

步骤 = JSON 对象，`type` 决定类型；执行引擎（`core/simulator.py`）按 `type` 分派。示例文件 `config/steps/VRV6_2P787591-1.json`：

```json
[
  { "type": "launch", "path": "C:\\Users\\Public\\Desktop\\ISP300Host_ver5.lnk" },
  { "type": "wait",   "seconds": 8.0 },
  { "type": "click",  "point_name": "CPU选择" },
  { "type": "type",   "text": "STM32H743" },
  { "type": "click",  "point_name": "STM32H743XI" },
  { "type": "key",    "key": "P" },
  { "type": "wait",   "seconds": 2.0 }
]
```

### 七类步骤的完整字段

**① 打开软件 `launch`** — 启动外部程序：

```json
{ "type": "launch", "path": "C:\\...\\ISP300Host_ver5.lnk" }
```

**② 点击 `click`** — 三种写法：

```json
{ "type": "click", "point_name": "CPU选择" }
{ "type": "click", "point_name": "CPU选择", "button": "left" }
{ "type": "click", "x": 805, "y": 337, "button": "left" }
```

> 按 `point_name` 调用时：若点位是控件点则走 UIA 点击，是坐标点则平滑移动鼠标点击；`button` 缺省时沿用点位自身记录的按键方式。UI 上新增点击步骤时会**强制显式选择** left / right / double。

**③ 选择文件 `openfile`** — 自动填充弹出的系统"打开文件"对话框（三种模式）：

```json
{ "type": "openfile", "mode": "path",   "path": "C:\\fw\\RXF42JV5V1B_V03.i3s" }
{ "type": "openfile", "mode": "latest", "dir": "C:\\fw\\RXF42JV5V1B", "pattern": "*.i3s" }
{ "type": "openfile", "mode": "pick" }
```

| 字段 | 说明 |
|------|------|
| `mode` | `path` 固定路径 / `latest` 取目录内**修改时间最新**的匹配文件 / `pick` 执行前弹窗手选一次（选完当次生效，不写死到步序） |
| `path` | 固定文件路径（`mode=path` 必填；执行时校验存在，不存在则本步直接失败，不会干等对话框） |
| `dir` | 固件目录（`mode=latest` 必填；只扫描该层，不含子目录） |
| `pattern` | 文件名匹配（默认 `*.i3s`，大小写不敏感） |

> 执行机制：等待目标软件的"打开文件"对话框出现（最长 10s、可被"停止"打断）→ 自动填入路径 → 点"打开(O)"或回车确认。填入前会把路径**统一规范化为反斜杠绝对路径**（Tk 选择器返回的正斜杠形式 `C:/x/y` 会导致老式对话框报"文件名无效"）。若目标软件弹出的不是标准对话框、或系统控件结构特殊导致无法定位，本步会明确报错并提示人工完成这一次选择（不影响后续步骤继续）。

**④ 输入文本 `type`** — 在当前光标处逐字符输入，区分大小写：

```json
{ "type": "type", "text": "SN-12345" }
```

**⑤ 按键 `key`** — 单个按键（enter / tab / esc / f1~f12 / space / delete / up / down …）：

```json
{ "type": "key", "key": "enter" }
```

**⑥ 等待 `wait`** — 暂停指定秒数：

```json
{ "type": "wait", "seconds": 2.0 }
```

> **关于"步骤后等待"**：早期步序中的 `wait` 字段（如 `"wait": 0.5`）是"步骤结束后再停 N 秒"的遗留写法；当前执行引擎只对独立的 `wait` 步骤生效。需要某步之后停顿，请显式插入一条"等待"步骤，语义更清晰。

**⑦ 等待烧录结果 `waitresult`** — 监控"烧录完成"弹窗判定烧录成败（建议紧跟 `Send Data`）：

```json
{ "type": "waitresult", "timeout": 120 }
```

| 字段 | 说明 |
|------|------|
| `timeout` | 等待弹窗的总超时秒数（默认 `120`，可配置；超时未收到即失败） |

> 判定规则：每 0.5s 轮询一次 ISP300 的结果弹窗（标题为 `COMPLETE`，或正文含 `Verify OK`——兼容自绘无标题栏弹窗），正文含 `Verify OK` → 判定 OK 并**自动点「确定」关闭弹窗**（判定与确认一体，不残留、可循环烧录下一片）；内容非 OK（如 `Verify NG`）或超时未收到 → 判失败并**立即中止后续步骤**（该判定失败不受"失败即中止"开关影响，绝不把 NG/未完成当成功继续跑）。轮询期间按 ESC / 点「停止」可即时中止。

## 执行机制与重要行为

点击 **开始执行** 后，主窗口在**后台守护线程**中调用 `ExecutionSession.execute_steps(...)`（每次执行一个独立会话实例，状态互不残留）：

```
校验机种/累进/步序 → 切换英文输入法(如需要) → 启用 ESC 全局监听
    → 逐条执行步骤（先经校验层: 非法步骤跳过并计入失败; 日志[1/N] + 进度条）
    → 停止监听 → 恢复输入法(无论成败必然执行) → 汇总统计 → 完成/停止弹窗
```

- **鼠标平滑移动**：点击前 `moveTo(..., duration=0.2)` 平滑移动 → 停顿 0.2s → 点击，操作过程可视化；
- **输入法保护**：执行前（及 `type` 输入前）调用 Windows `imm32` API 把当前中文输入法**临时关闭**（切到英文模式，不换布局、不新增英文输入法），输出英文后再由 `try/finally` 保证把输入法重新开启（无论成败都恢复，不残留）；
- **ESC 一键中止**：执行期间程序启用**全局键盘监听**，随时按 **ESC** 即等价于点`停止`——当前步结束后立即中止，`wait` 长等待也会被即时唤醒；**执行不再受鼠标移动影响**（可放心触碰鼠标，消除产线振动误中断）；
- **手动停止按钮**：执行中点击 `停止` → 设置会话停止信号 → 当前步结束后立即中止；
- **失败即中止（默认开启，可关）**：任一步骤校验失败或执行失败都会**立即中止**后续步骤（`summary.aborted / aborted_at`），UI 红字警示"已中止于第 N 步"，防烧错；主窗口「失败即中止」勾选框取消后恢复"失败计 failed 并继续"的旧行为；
- **烧录结果判定**：`waitresult` 步骤轮询标题 `COMPLETE` 的弹窗（默认 120s / 0.5s 步进，可被停止打断）——正文含 `Verify OK` 判成功并自动关窗，超时或内容非 OK 一律判失败；
- **统计口径真实**：`execute_step` 返回 `(ok, message)` 结构化结果，启动失败 / 控件未找到 / 校验不通过等不再被计入"成功"，汇总含 `成功 / 失败` 分项；
- **长文本粘贴**：`type` 文本超过 `TYPE_PASTE_THRESHOLD`（40 字符）自动走剪贴板 + `Ctrl+V`（输入后自动清空剪贴板），短文本仍逐键模拟以保兼容；
- **失败策略可切换**：开启「失败即中止」（默认）时单步失败即整体中止并红字提示；取消勾选后恢复旧的"失败继续跑完全程"行为（结束时按失败统计）。两种模式的失败步骤日志都写明原因，供定位；
- **参数集中可调**：移动时长 / 停顿 / 键入间隔 / 粘贴阈值等全部在 `core/constants.py` 的 `SimulatorConfig` 中，改一处即全局生效。

> 提示：执行中鼠标可自由使用（已移除"鼠标移动即中止"）；如需中止，按 **ESC** 或点击 **停止** 即可。

## 常见问题

**Q1：坐标不准 / 点到了错误位置？**
坐标是绝对屏幕坐标。请保证：录制与执行时 ISP300 窗口位置一致（建议最大化）、显示器分辨率一致。更换显示器/分辨率后需重新录制坐标。若目标控件能被 UIA 枚举，改用**控件点**即可彻底规避窗口位移问题。

**Q2：执行太快，软件来不及响应？**
在关键操作之间显式插入「等待」步骤。经验值：启动软件后等 5~8s，涉及弹窗/加载的操作后等 1~2s。

**Q3：输入中文会乱码或不支持？**
`type` 通过模拟按键逐字符输入，仅支持可键入的字符；执行前会把中文输入法临时关闭（切到英文模式，**不换输入法、不新增英文键盘布局**，结束后自动重新开启中文输入法）。中文与复杂符号建议改用剪贴板方案（长文本自动走，见上），或把要输入的固定内容直接做成坐标点击下拉候选。

**Q4：执行中动了鼠标，程序会中止吗？**
不会。**v3.3 起已移除"鼠标移动即中止"机制**——执行期间可以自由操作鼠标（点击、查看其它窗口都不会误停），产线振动也不会触发中断。需要中止时请按 **ESC** 或点主窗口 `停止`。

**Q5：如何中止执行？**
按 **ESC**（程序执行期间全程全局监听）或点主窗口 **停止** 按钮：当前步结束后立即中止，`wait` 长等待也会即时响应。执行中关闭窗口会先弹确认（确认后线程随进程终止）。

**Q6：配置文件能手动编辑吗？**
可以，均为纯文本 UTF-8 JSON。注意：手动增删 `machines.json` 的机种/累进时，要同步维护 `config/steps/` 下对应的步序文件（空步序写 `[]`）；改完若有语法错误程序会回退默认值并在日志中告警。

**Q7：如何把配置带到另一台电脑？**
拷贝整个 `config/` 目录（最好连同 exe 所在文件夹一起）。注意：烧录器软件的绝对路径（`launch` 步骤中的 `path`）和屏幕坐标点需在新机器上核对/重录；控件点通常无需改动。

**Q8：程序启动报找不到 pyautogui / pynput / pywinauto？**
未安装依赖或解释器不一致。执行 `pip install pyautogui pynput pywinauto`，并确保与运行 `main.py` 的是同一 Python。

**Q9：想看更详细的执行日志？**
`logs/auto_isp.log` 为 DEBUG 级（含控件点击、输入法等细节），比界面日志更全；控制台只输出 INFO。该文件每次运行追加，可随时清空。

**v3.5（列表行定位 + 失败即中止 + 烧录结果判定，2026-09-08）**：
- **修复"控件[18]"仍失败**：日志确认失败原因为「未找到控件」——录制空槽位行标题是纯数字（`18`），执行 `Read I.S.P`/`LOAD` 后同一行被设备占用、标题变成 ` 18 <device> ...`（行首还带空格），标题精确匹配必然失配。现 ListItem 纯数字标题解释为**列表行号**定位（`select()+click`，与行内容刷新无关）；最终失败自动 dump 列表当前全部行标题到日志，留诊断证据；
- **失败即中止（产线防烧错）**：默认任一步骤失败立即中止（此前会继续点 `Send Data`，存在烧错芯片风险）；主窗口加「失败即中止」勾选，summary 增 `aborted / aborted_at`，UI 红字警示中止步号；
- **新增第 7 类步骤 `waitresult`（烧录判定）**：新增 `core/result_dialog.py` 轮询 ISP300 的 `COMPLETE` 弹窗（默认 120s / 0.5s 步进、可停止打断），正文含 `Verify OK` 判成功并自动点「确定」关窗；超时/内容非 OK 一律判失败；
- 测试扩至 **57 个用例**（新增失败即中止 / waitresult / 弹窗纯函数 / ListItem 行号分派）。
